The point

A search tool for the stuff you don't search every day.

QueryBit is for the moment when you know something is somewhere in an old folder, archive or document pile. You want to search it now, not build an index or install a stack of converters.

No index

Point QueryBit at a file, directory or archive and search what is there right now. Nothing has to run in the background.

One executable

Format support is built in. Copy QueryBit onto a machine and use it without assembling a separate document-search toolchain.

No silent “no match”

If a corrupt file, parser failure or safety limit makes a search incomplete, QueryBit reports that instead of quietly pretending nothing matched.

Formats

Mixed folders are the normal case.

Search ordinary text and structured files in the same pass, including archives inside archives. Results preserve where the match came from.

Origin
Built for the file you know exists — somewhere.

I’d be trying to find something from years ago, know it was somewhere in an old archive, and have no idea which ZIP it was in. Usually that meant unpacking a bunch of archives just to search the PDFs and documents inside them.

On Windows I normally use Everything; on Linux, I reach for grep. Other search tools cover parts of this workflow, but I use multiple machines and operating systems and didn’t want to maintain a collection of supporting tools for something I only need occasionally.

What I wanted was simpler: one executable I could copy onto almost any machine, point at a directory or archive, search immediately, and then forget about until I needed it again.

No index to build. No background service. No need to unpack everything first.
